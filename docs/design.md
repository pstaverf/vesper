# Vesper — архитектура (этап 0)

Реализация: Rust (edition 2021), один бинарник `vesper`.

Расширение исходников: `.vx` (см. раздел «Противоречия»).

## Противоречия в задании

1. Расширение файлов указано дважды и по-разному: `.vx` (раздел 1) и `.vsp` (разделы 2, 4, 7). Принято `.vx` как в разделе «О языке»: `bot.vx`, `vesper run bot.vx`. Если нужно `.vsp` — скажи до этапа 1, лексеру всё равно, меняется только CLI и примеры.
2. Язык реализации: в первом сообщении `[Rust]`, во втором `[УКАЗАТЬ: Python / Node.js / Go / Rust]`. Принято Rust.
3. В разделе 1 написано `vesper run bot.vx`, в разделе 4 этапа 7 — перезапуск «при изменении `.vsp`». Принято: следим за расширением `.vx`.
4. Требование «неизвестные поля в ответах сохраняются и доступны в Vesper» и «типы генерируются из спецификации» частично противоречат: жёстко сгенерированные структуры отбрасывают неизвестные поля. Решение: значения Telegram в Vesper — это динамические словари (`Map`) с сохранением всех полей как есть; сгенерированный слой — это таблица методов и полей для проверки аргументов и подсказок, а не сериализуемые структуры. Так обновление API не ломает старые боты и не теряет новые поля.

## Архитектура

```
.vx ──lexer──> Vec<Token> ──parser──> Program(AST) ──interp──> Value
                                                        │
                                                        └── tg::Backend (trait)
                                                              ├── HttpBackend  (реальная сеть)
                                                              └── MockBackend  (тесты)
```

Поток выполнения бота:

```
Updater (poll | webhook) ──> Update(Map) ──> Router ──> HandlerRef ──> Interpreter
                                  │                                      │
                                  └────────── ctx: msg, upd, cb, args ───┘
```

Ядро (лексер, парсер, интерпретатор) не знает про Telegram: единственный мост — трейт `Backend`
с методами `call(method, params, files) -> Value` и `poll(offset, timeout) -> Vec<Value>`.
Слой API подключается только в `tg/` и в генераторе.

Сквозные правила:

- Все значения — `Value`: `Null | Bool | Int(i64) | Float(f64) | Str(String) | List(Vec<Value>) | Map(BTreeMap<String, Value>)`.
- `Map` хранит всё, что пришло из Telegram, включая незнакомые поля. Доступ к отсутствующему полю даёт `null`, а не ошибку.
- Ошибки языка: `файл:строка:колонка: ошибка: текст` + строка исходника и подчёркивание. Ошибка парсинга фатальна; ошибка времени выполнения в обработчике печатается и обновление пропускается, бот продолжает работу (`--strict` — завершиться).
- Сеть: таймаут на каждый запрос, `429` → пауза `retry_after`, `5xx`/таймаут → экспоненциальный повтор (0.5s, 1s, 2s, 4s, до 5 попыток), затем ошибка.
- Токен: `VESPER_TOKEN`, затем `TELEGRAM_BOT_TOKEN`, затем `BOT_TOKEN` из окружения или из `.env` рядом с файлом бота. В коде бота токена нет.

## Зависимости и зачем

| Крейт | Зачем | Почему не std |
|---|---|---|
| `serde_json` | разбор/сборка JSON Bot API, сохранение неизвестных полей | писать свой JSON-парсер — 400+ строк и баги на Unicode-эскейпах |
| `ureq` (rustls) | HTTP-клиент для Bot API и скачивания спецификации | std не умеет HTTP; rustls убирает зависимость от OpenSSL при статической сборке |
| `tiny_http` | webhook-сервер (этап 5) | std нет HTTP-сервера; крейт ~без зависимостей |

CLI-аргументы, `.env`, слежение за файлом, diff — своим кодом, без `clap`/`dotenv`/`notify`.
Точные версии фиксируются в `Cargo.lock` на этапе 1.

## Заметки для парсера (этап 2)

- Текущее состояние читается функцией `get_state()`, переменной `state` нет: `state` — только
  ключевое слово блока `state "имя":`. Парсер не принимает ключевые слова в позиции операнда.
- Имена именованных аргументов могут совпадать с ключевыми словами: `send("x", inline = kb)`,
  `send("x", menu = menu[["Да"]])`, `send("x", link = ...)`, `send("x", switch = ...)`.
  Парсер обязан принимать `Kw(...)` в позиции имени аргумента, лексер при этом не меняется.
- Подстановка `{…}` приходит из лексера уже разобранной на токены (`StrPart::Expr`).
  У неё собственная вложенность скобок: скобки внутри `{…}` не влияют на `INDENT`/`DEDENT`
  и на стек скобок внешнего выражения. Парсер разбирает эти токены как обычное выражение.

## Интерпретатор ядра (этап 3)

### Семантика значений

`Value::Str(Rc<str>)`, `Value::List(Rc<RefCell<Vec<Value>>>)`, `Value::Map(Rc<RefCell<BTreeMap<..>>>)`.

Почему `Rc<RefCell<..>>`, а не владеющие значения:

- `push(l, x)` и `pop(l)` описаны в `docs/syntax.md` как изменяющие список, поэтому список должен
  быть разделяемым: `a = []`, `b = a`, `push(b, 1)` — и `a` тоже видит элемент;
- копирование на каждом присваивании сделало бы `a = b` в цикле квадратичным на больших апдейтах
  (апдейт Telegram — это словарь на десятки килограммов памяти).

Клонирование `Value` клонирует только `Rc`, поэтому присваивание дешёвое, а данные общие.

`Rc<RefCell>` не запрещает циклические значения: `a = []`, `push(a, a)` или `a["x"] = a` создают
цикл. Защита встроена в три места, каждая с лимитом `MAX_VALUE_DEPTH = 100`:

- `json_write` (её использует `json(x)`, вывод списка/словаря в подстановке и `Value::display`)
  при глубине больше 100 возвращает ошибку «цикл или слишком глубокая вложенность»;
- `Value::display` не паникует: при ошибке возвращает `<цикл или слишком глубокая вложенность>`;
- `equals` при глубине больше 100 считает значения не равными (сравнение по `Rc::ptr_eq` для
  одного и того же объекта по-прежнему даёт `true`);
- ручной `Debug for Value` использует тот же лимит, поэтому `{:?}` в тестах и логах не вешает процесс.

### Области видимости

- верхний уровень файла пишет в глобальную таблицу;
- вызов функции создаёт ровно один фрейм: параметры и все присваивания внутри функции — локальные;
- блоки (`if`, `while`, `for`) фрейма не создают;
- чтение: сначала последний (текущий) фрейм, затем глобальная таблица. Фреймы вызвавшего
  **не видны** — динамической области видимости нет;
- запись: только в текущий фрейм (на верхнем уровне — в глобальную таблицу). Переменная
  становятся локальной при первом присваивании.

### Отрицательные индексы

`l[-1]` — последний элемент, `l[-len]` — первый, дальше — `null`. То же для строк.
Обоснование: чтение вне границ в языке мягкое (`null`), иначе `msg.text[0]` на пустой строке
ронял бы весь обработчик. Присваивание — наоборот, строгое: `a[-5] = 1` при длине 3 даёт ошибку
«выход за границы списка», потому что молча создавать элемент нельзя.

### Числа

`/` всегда float, `//` — целочисленное с округлением к минус бесконечности (`-7 // 3 == -3`),
`%` — остаток с знаком делителя (`-7 % 3 == 2`), `int + float` даёт float. Все операции над `int`
проверяются `checked_*`, переполнение — ошибка с позицией. Деление и остаток на ноль — ошибка.

Float-арифметика (`+ - * / %`) проходит через одну функцию `float_of`: если результат `inf` или
`NaN`, это ошибка «переполнение float: результат не число», а не тихое `inf` в значениях.

Сравнение `int` и `float` точное: если float целый и попадает в диапазон `i64`, сравнение идёт
как `i64` (поэтому `9007199254740993 == 9007199254740992.0` — `false`, хотя `f64` их путает),
иначе — как `f64`. Отрицание, `//`, `%`, деление на ноль и переполнения покрыты тестами.

Сравнение через `<`, `<=`, `>`, `>=` работает только для `int`/`float` (между собой), `string`
и `list` (поэлементно, только числа или только строки). `bool` и `bool` через `<` — ошибка
«нельзя сравнить bool и bool через '<' или '>'»: у `bool` нет порядка, только `==` и `!=`.
Словари через `<` — тоже ошибка. Разные типы — ошибка «нельзя сравнить X и Y: разные типы».

### Прерывание: `exit()`

`exit(code)` прекращает программу немедленно в любом месте: внутри `while`, `for`, функции,
вложенного блока и обработчика. Реализация — флаг `Ctx::exit` плюс `Flow::Exit`, который
пробрасывается из `exec_block`, `while`, `for` и вызова функции; `eval` после `exit()` ничего
не вычисляет и возвращает `null`, поэтому побочные эффекты после `exit()` не выполняются.
`run_handler` при этом возвращает `null`.

### Стек и глубина рекурсии

`MAX_DEPTH = 100` вызовов Vesper-функций. Замер: один вызов занимает ~16 КБ стека Rust в debug-сборке
(профиль `dev`, без оптимизаций), поэтому 100 вызовов укладываются в стандартный стек тестового
потока 2 МБ; тест `лимит_глубины_рекурсии_на_стеке_2_мб` это проверяет и получает `Diag`, а не
падение процесса. Для боевого запуска есть `run_with_stack(f)` — выполняет замыкание в потоке с
32 МБ стека (`STACK_SIZE`); цикл обновлений на этапе 5 будет работать внутри такого потока,
поэтому `Ctx` никогда не покидает поток.

### Встроенные функции: поведение на пустых и неверных значениях

| Функция | Пустое | Неверное |
|---|---|---|
| `len(x)` | `len("") == 0`, `len([]) == 0`, `len({}) == 0` | не строка/список/словарь — ошибка |
| `str(x)` | `str(null) == "null"`, float `1.0 → "1.0"` | ошибок нет, принимает всё |
| `int(x)` | `int(null) == 0`, `int("")` — ошибка | `int([1])` — ошибка, `int("abc")` — ошибка |
| `float(x)` | `float(null) == 0.0`, `float("")` — ошибка | `float([1])` — ошибка |
| `bool(x)` | `bool("") == false`, `bool(0) == false` | ошибок нет |
| `type(x)` | `type(null) == "null"` | ошибок нет |
| `keys/values(m)` | `keys({}) == []` | не словарь — ошибка |
| `has(m, k)` | `has({}, "a") == false`, `has([], 1) == false` | ключ не строка у словаря — ошибка |
| `push(l, x)` | `push([], x)` работает | не список — ошибка |
| `pop(l, i)` | `pop([]) == null`, индекс вне границ → `null` | индекс не int — ошибка |
| `join(l, sep)` | `join([]) == ""`, разделитель по умолчанию `""` | не список и не строка — ошибка |
| `split(s, sep)` | `split("") == [""]`, `split("", "") == []`, пустой sep режет на символы | не строка — ошибка |
| `trim/lower/upper(s)` | пустая строка → пустая | не строка — ошибка |
| `replace(s, a, b)` | замена пустой подстроки — ошибка | не строка — ошибка |
| `find(s, n)` | не найдено → `-1` | неверный тип — ошибка |
| `slice(s, a, b)` | индексы обрезаются к длине, `a > b` → пусто | не число — ошибка |
| `range(a, b, step)` | `range(0) == []`, шаг 0 — ошибка, больше 1 000 000 — ошибка | не число — ошибка |
| `random()` | `random([]) == null`, `random("") == ""`, `random(0) == 0` | не число/список/строка — ошибка |
| `now()` | всегда int из `EnvCtx` | ошибок нет |
| `json(x)` | `json(null) == "null"` | NaN/бесконечность и цикл — ошибка |
| `parse_json(s)` | пустая строка — ошибка с позицией | не строка — ошибка, глубже 100 уровней — ошибка |
| `log(x)` | пишет в `ctx.logs` | ошибок нет |
| `exit(code)` | `exit()` → код 0 | код не int/float/строка — ошибка |

`random` и `now` берутся из трейта `EnvCtx` (`rand`, `now`), поэтому в тестах используется
`FixedEnv` с фиксированными значениями. Реальный генератор — xorshift на std, без зависимостей.

Опущенные аргументы: позиционные заполняют слоты по порядку, именованные — по имени; пропущенные
в середине становятся `null`, пропущенные в конце просто отсутствуют. Лишний позиционный аргумент,
неизвестное имя аргумента и повторный аргумент — ошибки с русским текстом.

### Отличие от этапа 6

`run_handler(ctx, program, handler, vars, env)` и `handler_table(program)` — единственная точка
входа для будущего слоя Telegram. Встроенные функции Telegram регистрируются через
`Ctx::register(name, Builtin::new(&["позиционные"], замыкание))`, ядро о них не знает.

### Кнопки

`inline[...]` собирается в `{"inline_keyboard": [[{"text", "callback_data" | "url" |
"switch_inline_query"}]]}`, `menu[...]` — в `{"keyboard": [[{"text"}]], "resize_keyboard": true}`,
`menu[]` — в `{"keyboard": [], "resize_keyboard": true}`.

Использованные поля: `inline_keyboard`, `keyboard`, `resize_keyboard`, `text`, `callback_data`,
`url`, `switch_inline_query`. **Сверить по core.telegram.org/bots/api** (`InlineKeyboardButton`,
`KeyboardButton`, `ReplyKeyboardMarkup`, `InlineKeyboardMarkup`): имена полей, обязательность
`text`, максимальную длину `callback_data` (64 байта) и `switch_inline_query`.

## Слой API и обновляемость

`tools/gen_api` (Rust bin, входит в workspace) читает `api/spec.json`:

1. Проверяет версию и `release_date`.
2. Строит методы: имя, `returns`, параметры `{name, types, required}`.
3. Строит типы: имя, поля, признак union (`subtypes`) и `Array of` внутри полей.
4. Пишет `src/tg/gen.rs` (статические таблицы: `METHODS`, `TYPES`, const-имена методов).
5. Пишет/обновляет `api/api_version.json`.
6. Неразобранное поле или метод → предупреждение в stderr с именем метода и пропуск, код генерации 0.

Формат `api/api_version.json`:

```json
{
  "bot_api": "10.5",
  "release_date": "2026-11-22",
  "source": "https://github.com/PaulSonOfLars/telegram-bot-api-spec",
  "source_sha256": "<sha256 api.min.json>",
  "generated_at": "2026-11-23T07:40:00Z",
  "generator": "0.1.0",
  "methods": 194,
  "types": 426,
  "warnings": 0
}
```

Универсальный вызов:

```
res = call("sendMessage", {"chat_id": chat, "text": "ok"})
```

- Метод, которого нет в слое, вызывается всё равно (с предупреждением при `--strict`).
- Аргументы проверяются по слою: неизвестный параметр или неверный тип — предупреждение, запрос не блокируется.
- Ответ: `Map` как есть; неизвестные поля остаются; `ok = false` → `Error` с `description` и `error_code`.
- Путь: `call(...)` → `{base}/bot{token}/{method}` → разбор `{ok, result, description}`.

`vesper update-api`:

1. Скачивает `api.min.json` во временный файл, сверяет `sha256` при повторном запуске.
2. Генерирует новый слой в `tmp/gen_new.rs`.
3. Diff по структурам: `+ метод`, `- метод`, `~ метод: +параметр/-параметр/смена типа`, то же для типов.
4. Печатает diff и спрашивает подтверждение (`y/N`), при отказе ничего не меняет.
5. При подтверждении: текущий `gen.rs` → `api/history/gen-<версия>-<время>.rs`, пишет новую версию, обновляет `api_version.json`, дописывает запись в `api/changelog.md`.
6. `vesper update-api --rollback` возвращает предыдущий слой из `api/history/`.
